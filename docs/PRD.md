## 1. 개요

My Tasks는 설치나 서버 없이 HTML 파일 하나를 열어 바로 쓰는 개인용 할 일 관리 앱이다.
할 일을 업무·개인·공부 카테고리로 나누어 관리하고, 진행률을 한눈에 보며,
모든 데이터는 사용자의 브라우저(localStorage)에만 저장된다.

### 1.1 목표

- 할 일을 **빠르게 입력**한다 — 입력만 하면 키워드로 카테고리가 자동 선택된다.
- 진행 상황을 **한눈에 파악**한다 — 전체·카테고리별 진행률, 남은 개수, 응원 메시지.
- 실수를 **되돌릴 수 있다** — 삭제·가져오기 실행 취소, 중복 경고, 손상 데이터 보존.
- 휴대폰부터 큰 모니터까지 **어느 화면에서나** 편하게 쓴다 (반응형).
- 키보드·스크린 리더 사용자도 **모든 기능을 사용**할 수 있다.

### 1.2 대상 사용자

- 업무·개인 일정·학습을 한 곳에서 가볍게 관리하려는 개인 사용자
- 데스크톱 브라우저와 모바일 브라우저를 모두 사용하는 사용자
- 키보드 단축키를 선호하는 사용자, 보조 기술(스크린 리더) 사용자

### 1.3 범위 밖 (Non-goals)

- 계정, 로그인, 서버 저장, 기기 간 동기화
- 마감일·알림·반복 일정
- 여러 사용자 간 공유·협업
- 할 일 **수정** 시 자동 재분류, 기존 할 일 일괄 재분류 (백로그 — [TASK.md](./TASK.md) 참고)

## 2. 데이터 정의

할 일 1건은 다음 구조를 가진다.

| 필드 | 타입 | 설명 |
|---|---|---|
| `id` | string | 고유 ID (UUID, 미지원 환경에서는 시간+난수) |
| `text` | string | 할 일 내용. 앞뒤 공백 제거, 최대 200자 |
| `completed` | boolean | 완료 여부 |
| `createdAt` | string | 생성 시각 (ISO 8601) |
| `category` | `"work"` \| `"personal"` \| `"study"` | 카테고리 (업무 / 개인 / 공부) |

카테고리 색상: 업무 `#4A90E2`(파랑), 개인 `#27AE60`(초록), 공부 `#8E44AD`(보라).

## 3. 기능 요구사항

> 우선순위: **P0** 필수 / **P1** 중요 / **P2** 부가. 모든 항목은 현재 구현 완료 상태다.

### 3.1 할 일 기본 관리 (P0)

| ID | 요구사항 |
|---|---|
| FR-1.1 | 입력창에 내용을 입력하고 **Enter 또는 추가 버튼**으로 할 일을 추가한다. 빈 내용은 추가되지 않으며 입력창이 흔들리며 오류를 알린다. |
| FR-1.2 | 각 항목의 **× 버튼**으로 삭제한다. |
| FR-1.3 | **체크박스**로 완료/미완료를 전환한다. 완료 항목은 취소선과 흐린 색으로 표시된다. |
| FR-1.4 | 추가·삭제·완료 변경 시 **자동 저장**되고, 새로고침 후에도 유지된다. |
| FR-1.5 | 각 항목에 **생성 시간**을 상대 시간으로 표시한다 (방금 전 / N분 전 / N시간 전 / N일 전 / N주 전 / N개월 전 / N년 전). 마우스를 올리면 정확한 시각을 보여주고, 1분마다 갱신한다. |

### 3.2 카테고리와 필터 (P0)

| ID | 요구사항 |
|---|---|
| FR-2.1 | 할 일 추가 시 **카테고리 드롭다운**(업무/개인/공부)으로 카테고리를 고른다. |
| FR-2.2 | 각 항목에 카테고리 **색상 태그**와 왼쪽 색 테두리를 표시한다. |
| FR-2.3 | **필터**(전체/업무/개인/공부)로 목록을 거른다. 선택된 필터는 강조 표시되고, 필터 상태는 저장된다. |
| FR-2.4 | 특정 카테고리 필터를 선택하면 새 할 일의 기본 카테고리도 그 카테고리로 맞춘다. |

### 3.3 키워드 자동 분류 (P1)

| ID | 요구사항 |
|---|---|
| FR-3.1 | 새 할 일을 입력하는 동안 내용의 **키워드로 카테고리를 자동 선택**한다 (예: "팀 회의 자료" → 업무, "토익 단어 외우기" → 공부). |
| FR-3.2 | 자동 선택 시 드롭다운을 잠깐 강조하고, 입력창 아래에 `자동 분류: 업무 · '회의'`처럼 **근거 키워드**를 안내한다. |
| FR-3.3 | 키워드가 없으면 기본 카테고리(사용자가 마지막으로 고른 값 또는 필터 카테고리)를 사용한다. |
| FR-3.4 | 사용자가 드롭다운을 **직접 바꾸면** 그 항목에 대해서는 자동 분류가 덮어쓰지 않는다. 추천이 다르면 `추천: 업무 [적용]`으로 제안만 한다. 추가하거나 입력창을 비우면 자동 분류가 다시 동작한다. |
| FR-3.5 | 입력 직후 바로 Enter를 눌러도 분류 결과가 반영된다. 추가 알림에 자동 분류 여부를 표시한다. |
| FR-3.6 | "키워드 자동 분류" 체크박스로 켜고 끌 수 있으며 설정은 저장된다 (기본: 켜짐). |

### 3.4 검색과 정렬 (P1)

| ID | 요구사항 |
|---|---|
| FR-4.1 | 검색창에 입력하면 **실시간으로** 목록을 거르고, 일치하는 부분을 강조한다. ESC로 검색어를 지운다. 카테고리 필터와 함께 적용된다. |
| FR-4.2 | 정렬 방식: **완료 상태순**(기본, 미완료 위·완료 아래) / **직접 정렬** / **생성일순(최신)** / **카테고리순**. 선택한 정렬은 저장된다. |
| FR-4.3 | '완료 상태순'과 '직접 정렬'에서는 **드래그 앤 드롭**(마우스·터치)으로 순서를 바꾼다. '완료 상태순'에서는 같은 그룹(미완료끼리, 완료끼리) 안에서만 이동한다. |
| FR-4.4 | 드래그 중 화면 가장자리에 가까워지면 **자동 스크롤**하며, 포인터를 멈춰도 계속 스크롤한다. ESC로 드래그를 취소한다. |
| FR-4.5 | 드래그 핸들에 포커스한 뒤 **↑/↓ 키**로도 순서를 바꿀 수 있다. |

### 3.5 인라인 수정 (P1)

| ID | 요구사항 |
|---|---|
| FR-5.1 | 할 일 텍스트를 **더블클릭**하거나 **수정(✎) 버튼**으로 편집 모드에 들어간다. |
| FR-5.2 | 편집 모드에서 텍스트와 **카테고리**를 함께 바꿀 수 있다. |
| FR-5.3 | **Enter 저장, ESC 취소.** 터치 환경을 위해 저장(✓)·취소(✕) 버튼도 제공한다. 편집 영역 밖을 클릭하면 저장한다. |
| FR-5.4 | 내용을 모두 지우고 저장하면 원래 내용을 유지한다. 수정한 내용이 다른 할 일과 같으면 경고 알림을 띄운다. |

### 3.6 진행률 대시보드 (P1)

| ID | 요구사항 |
|---|---|
| FR-6.1 | 전체 진행률을 `5/10 완료 (50%)` 형식과 **프로그레스 바**로 표시한다. |
| FR-6.2 | 카테고리별 미니 진행률(완료/전체)을 표시한다. |
| FR-6.3 | **오늘 추가된 할 일 개수**를 표시하며, 자정이 지나면 자동으로 갱신된다. |
| FR-6.4 | 제목 옆 **배지**에 남은 할 일 개수를 표시하고, 바뀔 때 튀는 효과를 준다 (0개면 초록색). |
| FR-6.5 | 완료율에 따라 **응원 메시지**를 표시한다 (할 일 없음 / 0% / 30% 미만 / 60% 미만 / 90% 미만 / 100% 미만 / 100%). |
| FR-6.6 | 대시보드는 필터와 무관하게 전체 기준으로 **즉시** 갱신된다. |

### 3.7 실수 방지와 복구 (P1)

| ID | 요구사항 |
|---|---|
| FR-7.1 | 같은 내용(공백·대소문자 무시)의 할 일을 입력하면 입력 중 **실시간 경고**를 표시하고, 추가 시 확인 다이얼로그를 띄운다. 기존 항목 위치를 강조한다. |
| FR-7.2 | 삭제 후 알림의 **'실행 취소'** 버튼(6초 표시) 또는 **Ctrl/Cmd+Z**로 복구한다. 최근 10개 작업까지 되돌릴 수 있고, 원래 위치로 복구된다. |
| FR-7.3 | **완료 항목 모두 삭제** 버튼(완료 개수 표시, 0개면 비활성)은 확인 다이얼로그를 거친다. 기본 포커스는 '취소'다. |

### 3.8 데이터 내보내기 / 가져오기 (P1)

| ID | 요구사항 |
|---|---|
| FR-8.1 | 현재 할 일을 **JSON 파일로 내보낸다** (`my-tasks_YYYY-MM-DD_HHmm.json`). |
| FR-8.2 | JSON 파일을 **업로드해 가져온다**. 이 앱의 내보내기 형식과 할 일 배열 자체를 모두 허용한다. |
| FR-8.3 | 현재 데이터가 있으면 가져오기 전에 **"백업 후 가져오기 / 백업 없이 가져오기 / 취소"**와 **"합치기 / 모두 바꾸기"**를 선택한다. 합치기에서는 같은 ID의 항목을 건너뛴다. |
| FR-8.4 | JSON이 아닌 파일, 빈 파일, 5MB 초과 파일, 깨진 JSON은 거부하고 이유를 알린다. 형식이 잘못된 항목은 건너뛰고 개수를 알린다. |
| FR-8.5 | 가져오기도 실행 취소할 수 있다. |

### 3.9 테마 (P1)

| ID | 요구사항 |
|---|---|
| FR-9.1 | 우측 상단 **토글 스위치**로 다크/라이트 모드를 전환한다. 다크 색상: 배경 `#1A1A1A`, 카드 `#2D2D2D`, 텍스트 `#E0E0E0`. |
| FR-9.2 | 선택한 테마를 저장하고, 새로고침 시 깜빡임 없이 적용한다. 직접 고른 적이 없으면 OS 설정을 따른다. |
| FR-9.3 | 테마 전환 시 색이 부드럽게 바뀐다. |

### 3.10 키보드 단축키 (P1)

| 단축키 | 동작 |
|---|---|
| `Alt+N` | 새 할 일 입력창으로 이동 |
| `Alt+1` ~ `Alt+4` | 필터 전환 (전체 / 업무 / 개인 / 공부) |
| `Alt+D` | 다크 모드 전환 |
| `/` | 검색창으로 이동 |
| `Ctrl+Z` / `Cmd+Z` | 삭제·가져오기 실행 취소 (입력창 안에서는 브라우저 기본 동작) |
| `Esc` | 수정 취소 / 드래그 취소 / 검색어 지우기 |
| `↑` `↓` (드래그 핸들에서) | 순서 변경 |

단축키는 한글 입력 상태에서도 동작해야 한다. 하단에 단축키 안내를 표시한다 (터치 기기·좁은 화면에서는 숨김).

### 3.11 부가 기능 (P2)

| ID | 요구사항 |
|---|---|
| FR-11.1 | **오늘의 격언**을 표시한다. 하루 동안 같은 격언이 나오고, ↻ 버튼으로 다른 격언을 무작위로 본다. |
| FR-11.2 | 모든 동작(추가·삭제·완료·수정·필터 단축키·테마·저장 실패 등)에 **토스트 알림**으로 피드백한다. 최대 3개까지 쌓이고, 마우스를 올리면 사라지지 않는다. |
| FR-11.3 | 빈 상태 메시지: "할 일이 없습니다. 추가해보세요!" / 검색 결과 없음 / 카테고리에 할 일 없음을 구분한다. |

### 3.12 반응형 레이아웃 (P0)

| 화면 | 레이아웃 |
|---|---|
| 480px 이하 (모바일) | 한 장의 카드. 모든 터치 대상 44px 이상, 필터 2×2 배열, 단축키 안내 숨김 |
| 481 ~ 1023px (태블릿) | 한 장의 카드, 최대 폭 760px |
| 1024px 이상 (데스크톱) | 왼쪽 고정 사이드바(제목·격언·진행률·필터) + 오른쪽 메인(검색·정렬 바 상단 고정, 입력 카드, 한 줄형 목록, 데이터 관리·단축키). 화면 전체 사용, 메인 최대 1280px |
| 1440px 이상 (큰 모니터) | 사이드바와 여백 확대 |
| 데스크톱 + 높이 860px 이하 (노트북) | 사이드바 압축 — 필터까지 한 화면에 표시 |

## 4. 비기능 요구사항

| ID | 분류 | 요구사항 |
|---|---|---|
| NFR-1 | 성능 | 할 일 100개 이상에서도 입력·검색·정렬이 부드러워야 한다. 검색과 저장은 디바운스하고, 바뀐 항목만 다시 그린다. |
| NFR-2 | 접근성 | 모든 컨트롤에 레이블을 제공하고, 키보드만으로 모든 기능을 쓸 수 있어야 한다. 삭제·편집 후 포커스를 적절한 위치로 옮기고, 검색 결과 수·순서 변경을 스크린 리더로 안내한다. |
| NFR-3 | 접근성 | '동작 줄이기' 설정 사용자에게는 애니메이션을 끈다. |
| NFR-4 | 신뢰성 | 저장소 사용 불가·용량 초과에도 앱이 멈추지 않아야 한다. 손상된 저장 데이터는 버리지 않고 별도 키에 보관한다. 페이지를 떠날 때 대기 중인 저장을 즉시 실행한다. |
| NFR-5 | 신뢰성 | 다른 탭에서 바꾼 데이터·테마를 반영한다. |
| NFR-6 | 보안 | 사용자 입력은 HTML로 해석하지 않는다 (XSS 방지). |
| NFR-7 | 이식성 | 빌드 과정·외부 라이브러리 없이 `index.html`을 브라우저로 열면 동작해야 한다. |
| NFR-8 | 입력 | 한글 IME 조합 중의 Enter로 저장·추가가 잘못 실행되지 않아야 한다. |

## 5. 알려진 제약

- `Alt+D`는 Chrome·Edge·Firefox의 주소창 단축키와 겹쳐 브라우저에 따라 동작하지 않을 수 있다.
- 두 탭에서 동시에 수정하면, 저장 대기 중인 탭의 내용이 다른 탭의 변경을 덮어쓴다 (마지막 저장 우선).
- 검색·정렬 바가 모든 화면에서 할 일 입력보다 위에 있다 (화면 순서와 Tab 순서를 일치시키기 위함).
- 데이터는 브라우저별·기기별로 따로 저장된다. 옮기려면 내보내기/가져오기를 쓴다.
